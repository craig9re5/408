# 套卷冲刺页面 UI 审计报告（V2）

> **审计日期**：2026-08-31
> **审计对象**：「套卷冲刺」页面（`app/study-dashboard.tsx` 3214–3653；答题卡弹窗 4827+；`app/globals.css` 3113–4692）
> **前置基线**：`docs/SPRINT_UI_AUDIT.md`（V1，commit `b88a562`）。V1 裁定的大部分问题已修复，本报告仅针对**当前代码现状**。

---

## 一、全站整体 UI 取向

### 1. 视觉风格：暖纸质学术人文风

| 维度 | 全站约定 |
|------|----------|
| 底色 | 米色画布 `#f2efe7`（`--canvas`）+ 暖白纸卡 `#fbfaf6`（`--paper`），全局覆 2.5% 噪点纹理 |
| 文字 | 墨黑 `#172129`（`--ink`）/ 灰绿 `#8b918f`（`--muted`） |
| 强调色 | 仅三个低饱和语义色：珊瑚 `#ef846d`、灰蓝 `#74a4b5`、灰绿 `#7cac85`，及其 rgba 变体 |
| 字体 | 标题与关键数字用 Noto Serif SC 衬线（`--serif`），正文用系统黑体（`--sans`） |
| 形制 | 卡片圆角 16px、1px `--line` 描边、柔和扩散阴影 `0 4px 20px rgba(35,42,44,.03)` |

### 2. 布局模式

- 200px 深色固定侧栏（`#111b24`）+ 暖色毛玻璃吸顶顶栏 + `min(1180px, 100%-64px)` 居中内容列；
- 内容以「卡片网格」组织：hero 大卡、bento 网格（`auto-fill, minmax(min(280px,100%),1fr)`）；
- 断点体系：980px（顶栏收缩）/ 768px（侧栏隐藏、转底部移动导航）/ 640px（网格转单列）。

### 3. 交互习惯与设计语言

- **hover 反馈**：`translateY(-1~-2px)` + 阴影加深，不用变色边框表达状态；
- **分段控件**：深色 navy 激活（area-switcher）或白底浮起激活（tab-group）两种既有形态；
- **轻提示**：全局 `feedback-notice` 顶部浮条；
- **确认体系**：自研 `confirm-overlay` + `confirm-dialog`（含 `--danger` 变体），删除模拟卷即走此模式；
- **可访问隐藏控件**：checkbox 用「1px + opacity:0」保留键盘可达（`.task-check input`，globals.css:449）。

### 4. 冲刺页相对 V1 基线已修复项（勿重复改造）

假变量已清除并全面迁移 token；完成态已加左侧绿条 + 年份 pill 反色；筛选器已加「类型/状态」文字标签；两区空状态已补齐；`minmax` 横向溢出已修复；字号下限已收敛至 10px；圆点 hover 放大已移除（改由整块热区反馈）；分数已做 clamp（`updatePaper` 1050–1053）；已补 640px 断点。

## 二、现存问题清单（按严重程度分级）

### P0 — 严重（功能性缺陷 / 数据风险）

#### P0-1 【可用性 · 布局】英语科目下「模拟试题」Tab 状态残留 → 整页空白

- **现象**：在 408/数学下选中「模拟试题」Tab 后切换到英语，类型 Tab 中「模拟试题」按钮被隐藏（3333 行条件渲染），但 `sprintTab` 状态未重置——真题区不满足 `tab === "all" || "past"`（3378），模拟区被 `activeArea !== "english"` 拦截（3516），**两个 section 均不渲染**，工具栏上三个类型按钮无一高亮。
- **成因**：`setActiveArea`（2603）未联动重置 `sprintTab`；隐藏按钮与状态重置二者只做了前者。
- **影响**：用户看到筛选栏以下整页空白，极易误判为「数据丢失」，且无任何指引恢复。
- **改进方向**：切换 area 时若 `sprintTab === "mock"` 则重置为 `"all"`；或将隐藏改为禁用态并提示「英语无模拟卷」。

#### P0-2 【交互反馈 · 安全】答题卡弹窗「一键清零」无确认，直接清空整卷记录

- **现象**：弹窗工具条「一键清零 🔄」（4889）直接调用 `clearPaperQuestions`（1371），一次性抹掉该卷的 completed、completedAt、score、durationMinutes、secondRound、secondRoundAt、questions、questionScores **共 9 个字段**，并随防抖自动同步云端。
- **成因**：该入口未接入站内已有的 `confirm-dialog` 确认体系（删除单张模拟卷都有 `pendingDeletePaperId` 确认弹窗，力度反而不对等）。
- **影响**：一次误触即丢失整卷做题记录且不可撤销，跨设备同步后无法找回。
- **改进方向**：参照删除模拟卷模式，引入 `pendingClearQuestionsPaperId` 状态，走 `confirm-dialog--danger`；文案明确列出将清除的内容。

### P1 — 中等（一致性断裂 / 明显体验缺陷）

#### P1-1 【一致性】答题卡弹窗仍是冷灰蓝霓虹 SaaS 色板，与页面主体两套语言

- **现象**：弹窗样式块（globals.css 3926–4533）大量使用 `#10b981 / #f59e0b / #ef4444 / #3b82f6 / #1e293b / #f8fafc` 等高饱和 Tailwind 色 + Consolas 等宽数字 + 发光 `box-shadow`（4454、4461、4468）。而**同一份做题数据**在卡片迷你热力图上用的是暖色 token（`--green` 灰绿 / `--coral` 珊瑚 / `#e8b277` 暖黄，3779–3793）。
- **成因**：V1 改造的 token 迁移只覆盖到页面主体，弹窗整块未迁移。
- **影响**：「正确」在卡片上是灰绿、点开弹窗变成霓虹绿——同一语义两种颜色；字体在滚动中从衬线跳变到等宽；发光效果全站无先例。用户每点开一次答题卡就进入「另一个产品」。
- **改进方向**：将弹窗色板迁移到 `--green / --coral / #e8b277 / --ink / --paper` 体系，数字改回 `--serif`，删除发光阴影；卡片与弹窗共用一套状态色变量（建议抽 `--state-correct / --state-partial / --state-wrong`）。

#### P1-2 【布局 · 响应式】顶栏科目切换器在 ≤980px 无法收缩，横向溢出

- **现象**：`.study-switchers.sprint-top-switchers` 固定 `width: 420px`（3275）、内部 `.area-switcher` 固定 172px（3281），选择器特异性（0,2,0 / 0,3,0）**高于** 980px 与 768px 断点中对 `.study-switchers`（769、794）和 `.area-switcher`（797）的覆盖规则，媒体查询全部失效。
- **成因**：sprint 顶栏覆写只写了桌面态，未在断点内补对应覆盖。
- **影响**：平板与手机下顶栏被迫保留 420px 宽，挤压标题甚至撑出横向滚动；移动端三科切换按钮文字可能换行溢出。
- **改进方向**：在 980px / 768px 断点内为 `.sprint-top-switchers` 补 `width: auto; flex: 0 0 auto`，为内部 `.area-switcher` 补自适应宽度。

#### P1-3 【可用性 · 可访问性】卡片 checkbox 用 `display:none` 隐藏，退出键盘 Tab 序列

- **现象**：`.bento-check-label input { display: none; }`（3615）使「已做 / 二刷」两个复选框无法被 Tab 聚焦，也无 `:focus-visible` 样式。
- **成因**：未沿用全站既有模式——`.task-check input`（449）用「绝对定位 1px + opacity:0」隐藏，保留焦点与键盘操作。
- **影响**：键盘用户与读屏用户无法操作卡片上的核心状态切换；与全站自身 a11y 约定不一致。
- **改进方向**：改为 `.task-check` 同款隐藏法，并补 `.bento-check-label input:focus-visible + .bento-check-box` 焦点环。

#### P1-4 【交互反馈】分数越界静默夹取，无任何提示

- **现象**：`updatePaper`（1050–1053）会将越界分数 clamp 到满分（150/100），但输入 `200` 只是悄悄变成 `150`，无提示、无红框、无浮条。
- **成因**：只在数据层做了夹取，未在表现层给反馈。
- **影响**：用户无法区分「我输入的值生效了」还是「被系统改了」，对分数这种关键数据尤其敏感。
- **改进方向**：clamp 触发时通过全局 `feedback-notice` 提示「已按满分 150 分修正」，或输入框即时抖动 + 边框变 coral。

### P2 — 较轻（打磨项）

#### P2-1 【信息架构 · 状态逻辑】「二刷」可在一刷前勾选，产生矛盾状态

- **现象**：`togglePaperSecondRound`（1070）无任何前置校验，未做的卷子可以勾「二刷」；取消「已做」时也不会联动清除「二刷」→ 卡片呈现「未做 + 二刷✓」的逻辑矛盾。
- **成因**：两个布尔字段相互独立，无状态机约束。
- **影响**：筛选「未完成」时混入已二刷的卷子，统计数据可信度下降。
- **改进方向**：勾选二刷时若未完成一刷则提示或自动补记一刷；取消一刷时联动清除二刷（可参照 `toggleLearned` 对 reviewed 的级联处理）。

#### P2-2 【信息密度 · 可读性】卡片热力图过密且缩写体系与弹窗不一致

- **现象**：280px 卡片内塞入年份 pill + 分数输入 + 2 个 checkbox（+ 删除钮）+ 40 个 6.5px 圆点 + 7 个题号 chip + footer；行标签用 `DS: / CO: / OS: / CN:` 缩写（1408–1413），而弹窗内用「数据结构 / 组成原理」全称——同一科目两套称谓；圆点详情全靠 hover `title`，触屏完全不可达。
- **成因**：桌面 hover 优先的设计，缺少触屏降级；缩写为省空间临时引入。
- **影响**：首屏认知负荷高；触屏用户只能看到色点却查不了含义；两套术语增加学习成本。
- **改进方向**：行标签与弹窗统一（建议直接用「数构/计组/系统/计网」中文简称，两侧一致）；热力图点击后弹窗内定位到对应分组；评估 6.5px 圆点是否可放大到 8px。

#### P2-3 【视觉层次】宏卡空数据态与分数输入宽度瑕疵

- **现象**：无成绩时平均分显示 `--`，但仍挂着 `/ 150 分` 单位（3235、3304），读起来像「-- / 150 分」；`.bento-score-input` 固定 42px 宽（3571），衬线 14px 下 `100.5` 这类 5 字符会溢出。
- **影响**：空态语义含糊；极端值显示截断。
- **改进方向**：`--` 态隐藏单位或改为「暂无成绩」；输入框宽度改为 `min-width: 42px; width: auto` 或按字符数自适应。

#### P2-4 【一致性 · 文案】弹窗按钮 emoji 与全站纯文本语言不符

- **现象**：「一键全对 🟢」「一键清零 🔄」及大量 `title` 中的 🟢🔴🟡，全站其余界面（侧栏、分析页、设置页）均为纯文本。
- **改进方向**：去除按钮内 emoji，状态语义交由颜色与文字承担（title 内 emoji 影响较小，可保留或一并清理）。

#### P2-5 【维护债】死代码残留

- `.sprint-btn-reset-all`：TSX 0 引用，CSS 仍有两处（4629、4634）；
- `.bento-mini-heatmap` 的 `has-data` / `is-empty` 修饰类（TSX 1464 输出）在 CSS 中无任何对应规则，属无效状态钩子。
- **改进方向**：直接删除，或按需补样式（推荐删除）。

## 四、建议修复顺序

1. **P0-1 + P0-2**：功能缺陷与数据风险，改动小、应最先修；
2. **P1-2 + P1-3 + P1-4**：窄屏溢出、键盘可达性、分数反馈，均为低风险局部改动；
3. **P1-1**：弹窗色板迁移，改动面最大（约 600 行 CSS），需整页回归；
4. **P2 全部**：随 P1-1 顺带打磨。
