# 408 学习进度网站 V1.1–V1.3 需求文档

> 基线版本：当前 V1 已具备科目切换、章节目录、章节展开/折叠、计划日期、学完日期、复习日期、科目进度展示。
> 本文目标：明确 V1.1–V1.3 为什么要改、改什么、怎么改，以及验收标准。
---

## 1. 产品目标与设计原则

这个网站的核心不是记录尽可能多的数据，而是让用户在打开页面后的几秒内回答三个问题：

1. 我现在学到哪里？
2. 我的实际进度是否偏离计划？
3. 哪些内容已经学完，哪些还没有复习？

后续迭代继续坚持以下原则：

- **目录是主界面。** 新功能不能明显挤压目录空间。
- **每个小节仍然只保留两个核心动作：学完、复习。** 不增加掌握程度、评分、笔记等字段。
- **主页只展示对决策有帮助的信息。** 避免为了“数据丰富”而增加图表。
- **计划可以调整。** 学习计划长期使用时一定会变化，系统应允许批量顺延，而不是要求逐条修改。
- **复习只记录实际发生，不自动预测时间。** 不引入“建议 7 天后复习”“下一次复习日期”等逻辑。
- **状态必须由数据推导。** 页面上的完成、逾期、当前学习等状态应有明确规则，避免人工维护多个相互冲突的字段。

---

# V1.1：计划执行状态与当前学习

## 2. 为什么要做 V1.1

当前 V1 已经可以记录“计划日期”和“实际完成日期”，但这些数据还没有被真正利用起来。

目前存在几个问题：

- 顶部的大号百分比容易被理解成“整个科目完成度”，但实际上主要反映第一遍学习进度；复习进度没有被清楚区分。
- “本周节奏 / 连续学习天数”的信息价值偏低。连续学习 2 天不能直接说明计划执行得怎么样。
- 页面已经有计划日期，但逾期与否仍需要用户自己判断。
- “当前学习”如果只取第一个未完成小节，在跳过某一节时会产生错误定位。
- 左侧/章节上的颜色如果只是装饰，会让用户误以为颜色代表某种状态。

V1.1 的目标是把已有数据转化成可读的学习状态，让主页从“记录表”升级为“进度控制页”。

---

## 3. V1.1 功能需求

### 3.1 第一轮进度与复习进度分开

#### 为什么改

“学完”和“复习”本来就是两个不同阶段。如果只显示一个 33%，用户无法判断 33% 指的是第一轮、复习，还是综合进度。

#### 怎么改

顶部科目卡片继续保留大号百分比，但明确标注为“第一轮”。同时增加一个次级复习进度。

建议展示：

```text
操作系统                 进行中

33%  第一轮
██████████░░░░░░░░░░

学完 6/18 小节   ·   复习 0/18 小节
当前学习：2.1 进程与线程简介
```

也可以保留双进度条：

```text
第一轮   33%  ██████░░░░░░
复习      0%  ░░░░░░░░░░░░
```

#### 计算规则

- `studyProgress = studiedCount / totalSectionCount`
- `reviewProgress = reviewedCount / totalSectionCount`
- 小节只有在 `studiedAt != null` 时计入 `studiedCount`
- 小节只有在 `reviewedAt != null` 时计入 `reviewedCount`

不计算加权综合进度。

#### 验收标准

- 已学 6/18 时第一轮显示 33%。
- 复习 3/18 时复习显示 17%。
- 第一轮 100%、复习 0% 时，页面不能让人误以为整个科目全部完成。

---

### 3.2 “总进度”改名为“时间进度”

#### 为什么改

按照0301开始准备复习，1218（星期五）结束复习的百分比来规划时间进度，有助于考生掌握时间进度，提高考生的紧迫性。

#### 怎么改

改成已经过去时间的百分比，即：今日-0301/1218-0301.

---

### 3.3 本周卡片改为“本周计划执行”
**注意：3.3暂时不做。**
**ignore 3.3**
#### 为什么改

“连续学习天数”不直接反映计划是否完成。本周真正有用的问题是：本周准备完成多少学习/复习动作，现在完成了多少。

#### 怎么改

将右上角“本周节奏”改为两行核心数字：

```text
本周计划
计划完成/复习 12 项
实际完成/复习 8 项
```

> UI 若坚持使用“小节”一词，可以显示“12 小节 / 8 小节”；但内部统计应按“动作”计数。一次“学完”算 1 项，一次“复习”也算 1 项。同一小节如果本周既学完又复习，计 2 项。

#### 计划值来源

为了不引入“复习预测日期”，V1.1 不自动推算本周应该复习哪些小节。

本周计划值使用**单一的周目标数字**：

```ts
weeklyTarget: number
```

用户可以点击本周卡片中的计划数字进行编辑，例如从 12 改为 14。

实际值由系统自动统计本周发生的学习/复习动作：

```ts
weeklyActual = count(studiedAt in currentWeek) + count(reviewedAt in currentWeek)
```

周定义：周一 00:00 至周日 23:59，按用户本地时区计算。

#### 视觉状态

- `actual < target`：显示普通状态，不提前判定失败。
- 到周日结束后仍未达标：历史周记录显示未完成。
- `actual >= target`：显示已达成本周目标。

不做“连续学习天数”作为主要指标。若保留，只能作为很弱的辅助信息。

#### 验收标准

- 用户可编辑本周目标。
- 勾选“学完”或“复习”后，本周实际数量立即更新。
- 取消勾选后，本周实际数量同步减少。
- 跨周后自动进入新的周统计。
**ignore 3.3**
---

### 3.4 自动判断计划状态：正常 / 当前 / 逾期 / 已完成

#### 为什么改

计划日期应该直接转化成状态提示，同时确保色彩明确现实状态，规范色彩使用。

#### 怎么改

每个小节根据 `plannedStudyDate`、`studiedAt` 和当前日期推导状态。

状态定义：

```ts
type StudyPlanStatus =
  | 'completed'
  | 'overdue'
  | 'due_today'
  | 'upcoming'
  | 'unscheduled';
```

规则优先级：

1. `studiedAt != null` → `completed`
2. `plannedStudyDate == null` → `unscheduled`
3. `plannedStudyDate < today` → `overdue`
4. `plannedStudyDate == today` → `due_today`
5. `plannedStudyDate > today` → `upcoming`

#### 视觉规则

不要给每行增加大标签，只用轻量提示：

- 已完成：绿色勾选；日期正常显示。
- 逾期：计划日期改为淡橙红色，可在行左侧出现 2–3 px 标记。
- 今天计划：使用主色高亮计划日期。
- 未来：普通灰色。
- 未设置：显示“未设置”。

章节卡片左侧竖线改为状态含义，而不是随机装饰色：

- 蓝色：当前学习章节
- 绿色：章节所有小节已学完
- 橙色：章节中存在逾期未完成小节
- 灰色：普通/尚未开始

优先级：当前章节 > 逾期 > 全部完成 > 普通。

#### 验收标准

- 计划 8 月 8 日、今天 8 月 10 日且未学完 → 自动显示逾期状态。
- 同一小节一旦学完，逾期状态立即消失。
- 章节只要包含至少一个逾期小节，就能在折叠状态下看出来。

---

### 3.5 “当前学习”支持自动定位 + 手动指定

#### 为什么改

纯自动定位会在用户跳过某一小节时失真；纯手动维护又容易忘记更新。

#### 怎么改

增加可选字段：

```ts
currentSectionId: string | null
```

逻辑：

1. 如果 `currentSectionId` 指向一个仍存在且未学完的小节，优先使用它。
2. 如果该小节被学完，自动清除手动指定。
3. 没有有效手动指定时，自动取当前科目中第一个未学完的小节。
4. 全部学完时显示“第一轮已完成”。

交互：

- 鼠标悬停小节行时出现弱化操作“设为当前”。
- 当前小节可显示一个非常轻的圆点/主色文字。
- 不增加永久占位的一整列按钮。

#### 验收标准

- 用户可将 2.4 设为当前，即使 2.1 仍未完成。
- 2.4 学完后自动回到第一个未完成的小节。
- 删除当前小节后不会出现无效引用。

# V1.2：计划编辑与整体顺延

## 4. 为什么要做 V1.2

学习计划在几个月内一定会变化。当前逐个小节修改日期的方式，适合初始化，但不适合持续维护。

真实场景通常是：

- 某一章比预期多学了一天；
- 临时休息两天；
- 前面某节卡住，后面的所有日期都要一起移动；
- 想重新安排某一章，而不是整个科目。

V1.2 的目标是让“调整计划”变成低成本操作，同时不破坏普通浏览时的简洁目录。

---

## 5. V1.2 功能需求

### 5.1 计划编辑模式

#### 怎么改

目录标题区域增加一个轻量入口：

```text
目录                         编辑计划
```

进入编辑模式后：

- 章节和小节仍保持原有布局；
- `plannedStudyDate` 变为可直接编辑的日期控件；
- 显示批量调整操作；
- “学完”“复习”仍可查看，但编辑模式下不强调操作。

退出编辑模式后恢复普通目录视图。

#### 非目标

- 不新增独立的复杂计划管理页面。
- 不做甘特图。
- 不要求拖拽时间轴。

---

### 5.2 章节级批量设置日期

#### 为什么改

新建一章计划时，不应该要求用户为 6 个小节逐条设置日期。

#### 怎么改

章节编辑区支持：

```text
第2章 进程与线程
计划区间：8月2日 — 8月4日
```

提供两种设置方式：

1. **统一日期**：章节内所有未设置的小节使用同一天。
2. **按天均分**：按小节顺序分配到日期区间内。

“按天均分”示例：4 小节，8 月 2 日—8 月 4 日：

```text
2.1 -> 08/02
2.2 -> 08/02
2.3 -> 08/03
2.4 -> 08/04
```

已经实际学完的小节默认不被批量修改计划日期，除非用户明确勾选“包含已完成项”。

---

### 5.3 后续计划整体顺延

#### 为什么改

这是长期使用时最高频的计划调整动作。

#### 怎么改

在小节或章节上提供：

```text
从这里开始顺延
+1 天   +2 天   +3 天   自定义
```

支持两种范围：

- 当前章节后续小节
- 当前科目全部后续小节

内部操作：

```ts
shiftPlannedDates({
  startSectionId,
  days,
  scope: 'chapter' | 'subject'
})
```

只调整 `plannedStudyDate != null` 的项目。

默认不修改已经学完的小节的计划日期。

#### 日期规则

V1.2 默认按自然日顺延，包括周末。

未来如果需要“跳过休息日”，另做设置，不在本版本处理。

#### 撤销

批量顺延后提供一次临时撤销：

```text
已将后续计划顺延 2 天   撤销
```

不需要完整的历史版本系统。

#### 验收标准

- 从 2.3 开始顺延 2 天后，2.3 及后续符合范围的小节日期全部 +2。
- 2.1、2.2 不变化。
- 已学完的小节默认不变化。
- 点击撤销可恢复本次批量修改。

---

### 5.4 计划区间自动汇总到章节

章节折叠状态下显示：

```text
第2章 进程与线程
计划：8月2日—8月4日
```

计算：

- 取章节内所有非空 `plannedStudyDate` 的最小值和最大值。
- 如果只有一个日期，显示 `计划：8月2日`。
- 如果全部为空，显示 `计划未设置`。

章节右侧进度建议改为：

```text
3 / 4
```

或更明确：

```text
已学 3/4
```

展开后可以看到复习状态，不必在折叠卡片中堆叠太多数字。

# V1.3：复习记录与目录筛选

## 6. 为什么要做 V1.3

V1 已经有“复习”复选框，但如果不定义约束和浏览方式，随着目录变长，复习状态会越来越难管理。

同时明确：**V1.3 不做自动复习时间预测。** 系统不根据“学完日期”推算 7 天后、14 天后应该复习，也不自动生成复习任务。

本版本只解决两个问题：

1. 复习数据保持合理一致。
2. 用户可以快速找到“已经学完但还没复习”的内容。

---

## 7. V1.3 功能需求

### 7.1 复习状态约束

#### 规则

- 未学完的小节不能标记为“已复习”。
- `reviewedAt != null` 必须满足 `studiedAt != null`。
- 正常情况下 `reviewedAt >= studiedAt`。

交互：

- 未学完时，复习框使用禁用态。
- 鼠标悬停可提示：“学完后可标记复习”。
- 学完后，复习框自动变为可用。

#### 取消“学完”时的处理

如果小节已经复习，又尝试取消“学完”，不能直接产生 `reviewedAt != null && studiedAt == null` 的非法状态。

弹出轻量确认：

```text
该小节已经记录过复习。
取消“学完”会同时清除复习记录。

取消操作   确认清除
```

确认后同时清空 `studiedAt` 和 `reviewedAt`。

#### 日期规则

- 勾选学完：默认写入当前日期。
- 勾选复习：默认写入当前日期。
- 日期允许手动修改。
- 手动修改复习日期早于学完日期时，阻止保存并给出提示。

---

### 7.2 目录筛选

目录标题右侧增加轻量筛选，不新增页面：

```text
目录   [全部] [未学完] [未复习] [逾期]
```

定义：

- 全部：显示全部章节和小节。
- 未学完：`studiedAt == null`
- 未复习：`studiedAt != null && reviewedAt == null`
- 逾期：`plannedStudyDate < today && studiedAt == null`

章节行为：

- 如果筛选后章节没有任何匹配小节，整章隐藏。
- 进入筛选模式后，包含匹配项的章节自动展开。
- 切回“全部”后恢复用户此前的章节展开/折叠状态。

#### 验收标准

- “未复习”不会显示尚未学完的小节。
- “逾期”不会显示已经学完的小节。
- 筛选不改变任何学习数据，只改变显示结果。

---

### 7.3 全部展开 / 全部折叠

随着 408 完整目录增加，需要提供快速浏览能力。

目录标题右侧提供一个菜单或图标：

```text
全部展开
全部折叠
```

要求：

- 仅改变章节 UI 状态。
- 不写入学习数据。
- 普通模式与筛选模式均可使用。

---

### 7.4 复习进度展示

V1.1 已在顶部科目卡片显示复习进度；V1.3 进一步确保所有复习相关数字都来自同一个数据源。

不增加：

- 下一次复习时间
- 复习倒计时
- 艾宾浩斯曲线
- 自动生成复习计划
- 二刷/三刷状态

一个小节始终只有一个“已复习”状态和一个 `reviewedAt` 日期。

# 8. Codex 实现注意事项

1. **先改数据与业务规则，再改视觉。** 进度、状态、筛选都应从统一数据模型计算。
2. 不要为了实现新功能给每一行新增大量永久按钮；使用 hover、菜单或编辑模式。
3. 批量修改计划前保留本次操作的旧值，以支持一次撤销。
4. 任何会导致 `reviewedAt != null && studiedAt == null` 的操作都必须被阻止。
5. 现有 V1 数据升级到新结构时，缺失字段使用安全默认值：
   - `currentSectionId = null`
   - `weeklyTarget = 0` 或首次打开时要求用户设置
6. V1.1–V1.3 不改变“小节只有学完、复习两个核心复选框”的交互原则。
7. 不创建“今日任务”的第二套任务数据；未来今日页应直接读取现有计划数据。
