# 手机端交互问题清单

检查基于 2026-09-26 的本地测试空间，使用浏览器响应式视口 390×844 和 320×740。逐页查看了进度、冲刺、今日、课表、分析、设置，以及日志编辑、答题卡和试卷云盘弹层。以下是本轮能复现或有明确代码证据的问题；浏览器模拟不能代替 iPhone Safari 实机验收。

## 处理进度

按本轮确认的方向，M02、M03、M04、M05、M06、M08、M09 已实现并通过本地验收；M10 是主观信息层级调整，也已实现。M01 和 M07 按要求保留现状。下文保留发现时的证据与原建议，便于之后复查。

## iPhone 实机反馈

### M11 · P1 · 进度页首屏看不到章节入口

- **状态**：已针对实机截图重排手机端进度页，仍待 iPhone Safari 再次确认。
- **位置**：进度页顶栏、学习概览、本周节奏与目录工具；[`study-dashboard.tsx`](../app/study-dashboard.tsx)、[`globals.css`](../app/globals.css)。
- **证据**：2026-09-26 用户提供的 iPhone Safari 截图中，进度卡和本周节奏占据大部分首屏，目录筛选与两个操作按钮再占两行；第一张章节卡直到固定底部导航后方才出现。
- **影响**：打开进度页时看不到可点的学习章节，主要任务入口被次级统计挤出首屏。
- **处理**：手机端将进度卡改为紧凑摘要，本周节奏缩为浅色横条；目录操作与标题同排，筛选独占下一行；学科选择显示中文名称，并统一顶部控件高度。固定导航与正文底部留白共用高度变量，增加滚动定位留白。
- **边界**：浏览器响应式预览不等同于真实 iPhone Safari；系统状态栏、动态地址栏和浏览器工具栏不可由网页直接控制。

## 已确认的问题

### M01 · P1 · 答题卡“一键清零”会直接抹掉整卷记录

- **状态**：暂不修改（用户决定）。

- **位置**：冲刺 → 答题卡；[`AnswerSheetModal.tsx`](../app/components/sprint/AnswerSheetModal.tsx#L107)、[`study-dashboard.tsx`](../app/study-dashboard.tsx#L1552)。
- **证据**：390px 弹层顶部有“一键清零”。按钮直接调用 `clearPaperQuestions`，该函数清除完成状态、得分、时长、二刷状态、全部题目和题目分数；没有确认、撤销或快照入口。设置页的“清空套卷完成记录”却有确认弹层。
- **影响**：手机上误触后可丢失整卷作答记录，且页面立即同步状态。
- **建议**：清零前明确列出将删除的数据并二次确认；更理想的是保留短期撤销。批量“全对”覆盖已有标记时也应提供撤销。

### M02 · P1 · “今日”中的七天课表压得过窄

- **状态**：已处理；手机端“今日”默认显示当天课程列表，完整周课表仍在独立课表页。

- **位置**：今日 → 复习课表；[`schedule.css`](../app/schedule.css#L983)、[`TimetableGrid.tsx`](../app/components/schedule/TimetableGrid.tsx#L71)。
- **证据**：390px 预览中课程按钮宽约 35px，七天同时显示；紧凑版 CSS 使用 `repeat(7, minmax(0, 1fr))`，时间文字为 8px，课程标题为 11px。
- **影响**：课程难以快速读清和准确点选，“今日”的主要信息被压成一张缩略图。
- **建议**：手机端默认展示当天或连续三天，提供日期切换；完整周视图放在课表页。

### M03 · P1 · 长页面滚动后顶栏的学科切换入口消失

- **状态**：已处理；溢出规则改为 `clip`，390px 滚动 266px 后顶栏顶部实测仍为 0。

- **位置**：进度页及全局顶栏；[`globals.css`](../app/globals.css#L210)、[`study-dashboard.tsx`](../app/study-dashboard.tsx#L2449)。
- **证据**：展开章节并滚动约 191px 后，`.topbar` 虽为 `position: sticky`，实测其顶部为 `-191px`；祖先 `.workspace` 设置了 `overflow-x: hidden`。
- **影响**：浏览长目录时切换学科、查看同步状态要回到页面顶部。
- **建议**：调整造成 sticky 失效的祖先溢出规则（可评估 `overflow-x: clip`），并在 390px/320px 和弹层状态下复查横向溢出。

### M04 · P1 · 高频控件的手机触控区域偏小

- **状态**：已处理本清单列出的控件；冲刺科目在窄屏改为独立一行，课表切周、云盘筛选、日志格式和进度日期提高触控高度。

- **位置**：冲刺、课表、云盘、日志工具栏、进度日期。
- **证据**：390px 实测冲刺顶栏学科按钮约 35×26px、试卷类型标签高 26px；课表周切换箭头约 28×28px；云盘筛选高 27px、搜索框高 30px；日志格式工具约 28×26px；进度计划日期按钮高 23px。相关样式见 [`globals.css`](../app/globals.css#L874)、[`schedule.css`](../app/schedule.css#L1218)、[`paper-netdisk.css`](../app/paper-netdisk.css#L229)、[`journal.css`](../app/journal.css#L882)。
- **影响**：手指操作更易点错，尤其是相邻的批量操作与日期编辑。
- **建议**：优先扩展实际点击区域到约 44px 高；拥挤的顶栏可在极窄屏改为两行，视觉尺寸可以保持紧凑。

### M05 · P2 · 目录筛选无结果时只有空白

- **状态**：已处理；空结果显示说明和“查看全部”，计数改为筛选结果，展开按钮禁用。

- **位置**：进度 → 目录“未新学”；[`study-dashboard.tsx`](../app/study-dashboard.tsx#L957)、[`study-dashboard.tsx`](../app/study-dashboard.tsx#L2600)。
- **证据**：当前 OS 已新学 18/18；点“未新学”后 `filteredChapters` 为空，目录下没有提示，标题仍写“5 章 · 18 小节”，操作仍显示“全部折叠”。
- **影响**：用户可能以为内容加载失败，且看不出是筛选导致的空白。
- **建议**：显示“本学科没有未新学小节”及“查看全部”按钮，数量改为匹配结果，空结果时隐藏或禁用展开操作。

### M06 · P2 · 独立课表的横向内容缺少提示

- **状态**：已处理；手机端课表上方增加滑动提示。

- **位置**：课表 → 竖向周课表；[`schedule.css`](../app/schedule.css#L195)、[`schedule.css`](../app/schedule.css#L831)。
- **证据**：390px 首屏只看到周一到周四，课表内部可横向滚动（网格最小宽 520px），界面没有文字或边缘提示说明周五至周日还在右侧。
- **影响**：用户可能漏看后半周课程，以为一周只有四天。
- **建议**：首次展示“左右滑动查看后续日期”，配合右缘渐隐或日期分页；可考虑保留当前日期列作为默认滚动位置。

### M07 · P2 · 分析热力图单日格子太小

- **状态**：暂不修改（用户决定）。

- **位置**：分析 → 打卡轨迹；[`analytics.css`](../app/analytics.css#L444)、[`AnalyticsActivity.tsx`](../app/components/AnalyticsActivity.tsx#L127)。
- **证据**：390px 实测每个可点格子约 17.6×17.6px。页面已有“查看每日打卡数据列表”作为替代，但放在热力图下方。
- **影响**：手指难以准确查看某天数据；键盘语义虽已提供，触控体验仍弱。
- **建议**：手机端提高格子间距和命中区域，或把每日列表改成更明显的移动端主入口。

### M08 · P2 · 日志编辑弹层的工具栏与预览占用过多手机空间

- **状态**：已处理；手机端默认编辑，预览切换展示，常用工具优先并提供“更多格式”。

- **位置**：今日 → 写今日记录；[`journal.css`](../app/journal.css#L1463)、[`JournalEditorModal.tsx`](../app/components/journal/JournalEditorModal.tsx#L629)。
- **证据**：390px 全屏弹层中，Markdown 工具按钮约 28×26px；未输入内容时，下半屏“实时渲染预览”仍为空白区域，编辑区和预览区各自滚动。
- **影响**：输入时可见正文空间偏少，格式工具易误触，滚动层级不易辨认。
- **建议**：手机端默认只显示编辑区，预览改为“编辑 / 预览”切换；常用格式保留首行，其余放入更多菜单。

## 主观设计建议

### M10 · P2 · 冲刺首屏统计卡片占据过多高度

- **状态**：已按用户决定处理；手机端改为紧凑双列概览，保留套数、进度和均分。

- **证据**：390px 首屏的“历年统考真题 0 套”和“模拟试题 0 套”两张卡片先后占据大部分屏幕，第一张可操作的真题卡落在底栏附近。两张卡片只有少量数字与空均分。
- **建议**：在手机上合并为较矮的双列概览，或在数据为空时压缩展示，把筛选和试卷列表提前。这是信息优先级建议，需结合你最常用的冲刺操作决定。
